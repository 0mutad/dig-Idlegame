## 2. ゲームエンジンを使わない判断

### 2.1 判断

**ゲームエンジン（Godot / Unity 等）は使わない。素の Canvas 2D と自前のゲームループで作る。**

### 2.2 理由

| 理由 | 説明 |
|---|---|
| エンジンの得意分野を使わない | 物理演算なし、画面は1つ（シーン遷移なし）、素材ファイルなし、アニメーションなし |
| **一番難しい要件がエンジンだと逆に難しくなる** | 「カードの外のクリックを下のアプリに通す」は Electron の標準機能（`setIgnoreMouseEvents(true, { forward: true })`）。Godot の組み込み機能（`mouse_passthrough_polygon`）は自分のウィンドウ内の当たり判定で、他アプリには通らない。Windows 専用の追加モジュールかネイティブコードが必要になる |
| 規模が小さい | コアロジックが635行で収まっている |

### 2.3 見直しの基準

次のどれかに当てはまり始めたら、エンジンへの移行を検討する。

- ドット絵のアニメーションが10種類を超える
- 画面（シーン）が複数になる
- 音を本格的に扱う（多重再生・フェード・空間配置）
- スマホにも出す

**判断する時期は「配布ビルドを通した後、アートを入れる前」**。アートを入れた後だと移植コストが跳ね上がる。

### 2.4 移行するとしたら

移行先は **Godot 4**。

| 持っていけるもの | 捨てるもの |
|---|---|
| `src/data.js` の全テーブル（地層・収集物・強化） | 描画コード（約300行） |
| バランス設計とシミュレータの検証結果 | HUD・パネルの HTML/CSS |
| ゲームルール（`ゲーム仕様.md`） | Electron まわり |

## 4. スクリプトの構成

### 4.1 読み込み順

`index.html` の末尾で、通常の `<script>` として次の順に読む。

| 順 | ファイル | 公開するもの |
|---:|---|---|
| 1 | `data.js` | グローバルに `RARITY` `STRATA` `UPGRADES` `ALL_ITEMS` `stratumAt()` `depthMult()` |
| 2 | `game.js` | なし（即時関数で閉じている） |
| 3 | `desktop.js` | なし（即時関数。`window.desk` がなければ何もしない） |

### 4.2 ES Modules を使わない理由

`index.html` をブラウザで直接開いたとき（`file://`）、`<script type="module">` はブラウザのセキュリティ制限で読み込めない。開発時に「ダブルクリックで開けば動く」状態を保つため、あえてグローバル定義にしている。

## 5. ゲームループ

```
requestAnimationFrame ごとに:
  dt = 前フレームからの経過秒（ただし最大0.1秒）
  update(dt)    状態を進める
  render()      Canvas を描き直す
  0.1秒に1回だけ paintHud()   HUD の DOM を更新
```

| 項目 | 仕様 |
|---|---|
| 更新頻度 | ディスプレイのリフレッシュレートに従う（通常60fps） |
| `dt` の上限 | **0.1秒**。タブ切り替えなどで間が空いても、一気に進みすぎないようにする |
| HUD の更新 | 0.1秒ごと。DOM の書き換えは重いので毎フレームはやらない |

> **注意**: `dt` の上限があるため、**`requestAnimationFrame` が止まっている間の時間はすべて失われる**。スリープ・ウィンドウの最小化・バックグラウンドでの間引きがこれに当たる（§10 の負債 #1）。

## 6. Electron の構成

### 6.1 プロセスの役割

| | ファイル | 役割 |
|---|---|---|
| メインプロセス | `electron/main.js` | ウィンドウの生成・配置。IPC を受けてクリック透過の切り替えと終了 |
| プリロード | `electron/preload.js` | `contextBridge` で `window.desk` だけをレンダラーに渡す |
| レンダラー | `index.html` + `src/*` | ゲーム本体。Node の機能には触れない |

### 6.2 IPC

| チャンネル | 方向 | 内容 |
|---|---|---|
| `desk:ignore` | レンダラー → メイン | `true` でクリック透過、`false` で解除 |
| `desk:quit` | レンダラー → メイン | アプリを終了する |

レンダラーからは `window.desk.setIgnore(bool)` と `window.desk.quit()` として呼ぶ。

### 6.3 セキュリティ設定

| 設定 | 値 |
|---|---|
| `contextIsolation` | `true` |
| `nodeIntegration` | `false` |
| レンダラーに渡す API | 上記2つの関数のみ |

### 6.4 ウィンドウの設定

| オプション | 値 | 理由 |
|---|---|---|
| `frame` | `false` | タイトルバーを出さない |
| `transparent` / `backgroundColor` | `true` / `#00000000` | カードの外を透明にする |
| `hasShadow` | `false` | 影は CSS でカードにだけつける |
| `resizable` | `false` | |
| `movable` | `true` | HUD をドラッグして動かす（`-webkit-app-region: drag`） |
| 最前面 | `setAlwaysOnTop(true, 'normal')` | |
| `skipTaskbar` | `false` | タスクバーに出す |
| 初期のクリック透過 | `setIgnoreMouseEvents(true, { forward: true })` | `forward` でマウス移動は受け取り続ける |

## 7. 保存

### 7.1 保存場所

| 環境 | 場所 |
|---|---|
| Electron（Windows） | `%APPDATA%\deskavation\Local Storage\` |
| ブラウザ | そのブラウザの `localStorage`（`file://` のオリジンごと） |

> **重要**: Electron の保存フォルダ名は `package.json` の `name`（現在 `deskavation`）から決まる。**タイトル変更などで `name` を変えると、既存のセーブが見つからなくなる。** 変えるなら移行処理が必要。

### 7.2 形式

キー `deskavation.save.v1` に、次の JSON を文字列で入れる。

```json
{
  "depth": 2633.4,
  "money": 6305,
  "upgrades": { "speed": 6, "click": 5, "bit": 4, "sonar": 3, "battery": 2 },
  "collection": {
    "pebble": { "count": 12, "firstDepth": 120 },
    "bone":   { "count": 2,  "firstDepth": 2200 }
  },
  "veinTimer": 87.2,
  "caught": 49,
  "missed": 0,
  "paused": false,
  "lastSave": 1761360000000
}
```

| フィールド | 型 | 意味 |
|---|---|---|
| `depth` | 数値（m） | 現在の深度 |
| `money` | 数値（G） | 所持金。小数を含みうる |
| `upgrades` | オブジェクト | 強化ID → Lv |
| `collection` | オブジェクト | 収集物ID → 個数と初めて見つけた深度 |
| `veinTimer` | 数値（秒） | 次の鉱脈までの残り時間 |
| `caught` / `missed` | 整数 | 回収数／失敗数（画面には未表示） |
| `paused` | 真偽値 | 保存はされるが、読み込み時に必ず `false` に戻す |
| `lastSave` | 数値（ミリ秒） | 保存時刻。放置精算の起点 |

### 7.3 読み込み時の扱い

1. 保存データを状態の初期値の上にそのまま上書きする（`Object.assign`）
2. `upgrades` は既定値（全部0）と合成する。**新しい強化を追加しても古いセーブで壊れない**
3. `collection` が無ければ空にする
4. `paused` は `false` に戻す
5. 読み込みや解析に失敗したら、新規ゲームとして始める（エラーは出さない）

### 7.4 互換性の現状

| 変更 | 古いセーブへの影響 |
|---|---|
| 状態に新しいフィールドを追加 | 問題なし（初期値が使われる） |
| 強化を追加 | 問題なし（Lv0 で補完） |
| 収集物を追加 | 問題なし |
| **収集物の ID を変更・削除** | **図鑑の記録が消える**（古い ID が宙に浮く） |
| **`package.json` の `name` を変更** | **セーブごと見つからなくなる**（§7.1） |
| 保存形式を大きく変える | キーの `v1` を上げ、移行処理を書く必要がある（未整備） |

## 8. 開発と実行

```bash
npm install          # 初回のみ。Electron を入れる
npm start            # デスクトップ常駐版を起動
```

ロジックだけ確認したいときは `index.html` をブラウザで開く。

```bash
node tools/balance-sim.js              # バランスの推移（アクティブ／放置、各120分）
node tools/balance-sim.js --base 2.5   # 価値の伸びを変えて比較
node tools/drop-rates.js               # 地層ごとの出現確率
```

セーブを消したいときは、`%APPDATA%\deskavation\` を削除する（ブラウザなら開発者ツールでキーを削除）。

## 9. 同じ値を複数箇所に書いているところ

1箇所だけ変えると不具合になる。変更するときはすべて直すこと。

| 値 | 書いてある場所 |
|---|---|
| カードの幅・高さ、パネルの高さ、余白 | `src/style.css`（`:root`）、`src/game.js`（`STRIP_H` `DRILL_Y`）、`electron/main.js`（`CARD_W` `STRIP_H` `PANEL_H` `MARGIN`） |
| 鉱脈の時間・自動ゲージ上限・初回の鉱脈 | `src/game.js`、`tools/balance-sim.js` |
| 抽選の式（レア度ボーナス） | `src/game.js` の `pickItem`、`tools/balance-sim.js`、`tools/drop-rates.js` |
| 強化の効果の式 | `src/game.js`（派生値）、`src/data.js`（説明文 `desc`） |
| 保存キー `deskavation.save.v1` | `src/game.js` |

## 10. 技術的負債

| # | 内容 | 影響 | 対応の目安 |
|---|---|---|---|
| 1 | **`requestAnimationFrame` が止まった時間が失われる** | 起動したままのスリープ・最小化・バックグラウンド中の進行が消える。常駐ツールとしては致命的 | Electron の `powerMonitor` の復帰イベント、または `Date.now()` の差分で放置精算を走らせる |
| 2 | **Electron 34 に既知の脆弱性**（`npm audit` で high） | Electron は製品に同梱されるので、配布物にそのまま含まれる | 配布前に最新の安定版へ更新 |
| 3 | `game.js` に状態・描画・UI・保存が同居（635行） | 機能追加のたびに見通しが悪くなる | アートや音を入れる前に分割 |
| 4 | テストがない | バランスや保存形式を変えたときの退行に気づけない | 最低限、保存の読み書きと抽選の式 |
| 5 | パネルを `innerHTML` で丸ごと作り直す | 図鑑のスクロール位置が飛ぶ（`画面仕様.md` §11） | 差分更新にする |
| 6 | 値の重複（§9） | 変更漏れ | 寸法は1箇所から配る、式は `data.js` に寄せる |
| 7 | 文言の直書き | 英語対応ができない | 文言を1ファイルにまとめる |
| 8 | 鉱脈の最中の状態を保存しない | 鉱脈中に終了するとその鉱脈が消える | 影響は小さい |
| 9 | 保存形式の移行処理がない | 形式を変えると古いセーブが壊れる | Steam 公開前に必須 |

## 11. Steam 販売に向けた技術課題

| 項目 | 必要な作業 | 状態 |
|---|---|---|
| 配布ビルド | `electron-builder` を入れて、Windows 用インストーラ／実行ファイルを作る | 未着手 |
| Electron の更新 | 最新の安定版へ（負債 #2） | 未着手 |
| Steamworks 連携 | `steamworks.js`（Electron / NW.js 向けの定番）を導入。ネイティブモジュールなので Electron のバージョンに合わせた再ビルドが必要 | 未着手 |
| 実績 | `steamworks.js` で対応可能 | 未着手（実績の設計自体が未決） |

| Mac 版 | ウィンドウ透過・クリック透過の挙動確認、コード署名の要否の確認 | 未検証 |
| 復帰時の精算 | 負債 #1 | 未着手 |
